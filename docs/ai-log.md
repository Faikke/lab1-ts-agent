## Промпт 1: manifest агента

**Запит:** Створити `.github/agents/build-engineer.agent.md` для агента, який автоматизує створення кросплатформного TypeScript Hello World (npm scripts, Vitest, GitHub Actions на Windows/Linux/macOS): роль, область відповідальності, правила роботи з файлами, заборонені дії, критерії завершення.

**Відповідь AI:** Створено manifest із роллю, ідемпотентними правилами, забороненими діями та критеріями. Збірку й тести AI не запускав.

**Проблема:** Розділ Skills описував загальні вміння (TypeScript, npm, Vitest), а не три skills з методички. Не було commands і оркестратора, вимоги, що `ci.yml` лише викликає `ci.sh`/`ci.bat`, критерію з `node build/hello.js` і документації.

**Виправлення:** Другим запитом попросив AI оновити manifest: конкретні skills (`project-scaffold`, `build-and-test`, `github-actions`), розділ Commands (`init` зупиняється на першій помилці, `check` нічого не змінює), правило про ci-скрипти, критерій `hello`, документація, заборона небезпечних дій без підтвердження.

**Рішення:** Переглянув diff, прийняв змінений manifest.

## Промпт 2: skills

**Запит:** Створити три skills (`project-scaffold`, `build-and-test`, `github-actions`) із frontmatter та розділами: коли застосовувати, вхідні дані з прикладом, вихідні файли, перевірки, типовий сценарій помилки. Усі ідемпотентні. `github-actions` створює `ci.sh`, `ci.bat` і `ci.yml` (одна job, matrix з трьох ОС, лише checkout, setup-node і виклик скрипта).

**Відповідь AI:** Створено три файли `SKILL.md` з усіма потрібними розділами.

**Проблема:** `project-scaffold` приймав мову привітання (`language`) без значення за замовчуванням, тоді як критерій завершення вимагає, щоб `node build/hello.js` виводив саме `Hello World`. Через це `check` не міг би однозначно перевірити вивід.

**Виправлення:** Додатковим запитом попросив зробити `language` необов'язковим зі значенням English, щоб `src/hello.ts` виводив рядок `Hello World`.

**Рішення:** Переглянув кожен skill, перевірив, що вони лежать в окремих файлах і не дублюють відповідальність: `project-scaffold` не чіпає збірку, `build-and-test` не чіпає CI, `github-actions` не містить команд збірки у workflow. Прийняв зміни.

## Промпт 3: commands

**Запит:** Створити в `.github/prompts/` шість команд: `git-init`, `create-project`, `create-build`, `create-actions`, `check`, `init` (frontmatter з `description` і `agent: Build Engineer`). У кожній: передумови, дії, очікувані файли, команди перевірки, повідомлення про помилку. `create-*` викликають відповідні skills, `check` нічого не змінює, `init` запускає git-init, create-project, create-build, create-actions, check по черзі й зупиняється на першій помилці. Усі команди ідемпотентні, нічого не видаляють.

**Відповідь AI:** Створено шість `.prompt.md` файлів з усіма потрібними розділами. `init` працює за принципом fail-fast і вважає успіхом лише успішний `check`.

**Проблема 1:** Жодна команда не створювала `docs/architecture.md` і `docs/usage.md`, хоча `check` вимагає їх наявності. Перший запуск `/init` впав би на `/check`, а агент не відтворював би весь результат з нуля.

**Виправлення 1:** Додатковим запитом попросив додати створення цих двох файлів (лише якщо відсутні) у `create-project` та skill `project-scaffold`.

**Проблема 2:** `check` не враховував відсутність `node_modules/`, тож `npm run build` міг упасти без зрозумілого пояснення.

**Виправлення 2:** Додатковим запитом попросив `check` перевіряти наявність `node_modules/` перед збіркою і повідомляти блокер із порадою виконати `npm ci`, не змінюючи файли (щоб зберегти read-only).

**Рішення:** Переглянув diff кожного prompt-файлу, перевірив порядок викликів в `init` і що `check` не містить команд, які змінюють файли. Прийняв зміни.

## Запит 5: локальна перевірка

**Проблема:** `npm run build` у PowerShell впав з `running scripts is disabled on this system` (політика виконання скриптів Windows блокує `npm.ps1`). `node build/hello.js` при цьому працював.

**Виправлення:** `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`. Помилка середовища, не проєкту; manifest, skills і commands не змінювалися.

## Запит 6: README

**Проблема:** Після `init` агент замінив мій `README.md` мінімальним текстом без ПІБ, групи і варіанта, всупереч правилу ідемпотентності.

**Виправлення:** Відновив ці дані в README і попросив уточнити skill `project-scaffold` та `create-project`: існуючий README не перезаписувати, лише доповнювати.

 ## Запит 7: тригери CI

## Запит 9: помилка синтаксису workflow

**Проблема:** Обидва запуски CI впали з `Invalid workflow file ... Unrecognized named-value: 'runner'` (вираз `runner.os == 'Windows' && 'cmd' || 'bash'` у `shell:`). Контекст `runner` недоступний у цьому полі.

**Виправлення:** Попросив агента замінити один крок на два з умовами `if: runner.os ...` і явним `shell`, а також оновити skill `github-actions`, щоб це не повторювалось.

**Перевірка:** Повторно запустив `init` на готовому проєкті для перевірки ідемпотентності.

**Результат:** Агент не створив і не дублював файли, `docs/ai-log.md` не змінював. `ci.bat`, `npm run build`, `npm test`, `npm start`, `node build/hello.js` пройшли, `build/` і `node_modules/` ігноруються Git. Linux і macOS локально не перевірялись, їх покриває GitHub Actions. `git status` чистий.
